# sankhya

> **sankhya** (Sanskrit: सांख्य — enumeration / analysis) — ancient mathematical systems, historical calendars, and archaeoastronomy for AGNOS

Faithful implementations of computational traditions from eight civilizations, 10+ calendar systems, and archaeoastronomy tools — with cross-civilizational epoch correlation. Every algorithm cites its primary source. No other library in any language covers this scope.

Part of the [AGNOS](https://github.com/MacCracken/agnosticos) ecosystem; the primary consumer is [hisab](https://github.com/MacCracken/hisab) (arithmetic), as an optional companion.

## Modules

| Module | Civilization | Era | Highlights |
|--------|-------------|-----|------------|
| `mayan` | Maya | 2000 BCE+ | Vigesimal (base-20), Long Count calendar, Tzolkin, Haab, Venus tables, Calendar Round search |
| `babylonian` | Babylon | 2000–300 BCE | Sexagesimal (base-60), Saros cycle, Plimpton 322 triples, Heron's sqrt, lunar calendar, cuneiform display |
| `egyptian` | Egypt | 2000–1000 BCE | Unit fractions (Rhind Papyrus), doubling multiplication, stellar decans, Sothic cycle, hieroglyphic display |
| `vedic` | India | 800 BCE+ | Nikhilam multiplication, Sulba Sutra geometry, Katapayadi, Meru Prastara, Devanagari display |
| `chinese` | China | 500 BCE+ | Rod numerals, Chinese Remainder Theorem, magic squares, Sexagenary 60-year cycle, Unicode rod display |
| `greek` | Greece | 600 BCE–300 CE | Golden ratio, Sieve of Eratosthenes, Euclidean GCD, Archimedes' pi, Antikythera, isopsephy |
| `roman` | Rome | 500 BCE+ | Roman numeral conversion (I–MMMCMXCIX), canonical validation, arithmetic |
| `islamic` | Islamic Golden Age | 750–1258 CE | Al-Khwarizmi algebra, Khayyam cubics, completion of the square, Hijri calendar |
| `gregorian` | Global | 1582 CE+ | Proleptic Gregorian calendar, JDN conversion, leap years |
| `coptic` | Egypt/Ethiopia | 284 CE+ | 13-month Alexandrian calendar, Anno Martyrum |
| `persian` | Iran | 622 CE+ | Solar Hijri (Jalaali), 2820-year leap cycle, Nowruz |
| `hebrew` | Israel | 3761 BCE+ | Lunisolar, Metonic cycle, molad, dehiyyot, 6 year types |
| `aztec` | Mesoamerica | 1200–1521 CE | Tonalpohualli (260-day), Xiuhpohualli (365-day), Calendar Round |
| `epoch` | Cross-civilizational | — | Precession, precessional ages, Seven Sages, cycle alignment, unified `correlate()` / `convert()` API |
| `astro` | Archaeoastronomy | — | Coordinate systems, star catalog, precession, heliacal rising, monument alignment |

Under the domain modules sits a foundation layer (`error`, `util`, `f64_util`, `logging`), a per-module `serial_*.cyr` JSON layer, an `lib.cyr` aggregator, and a minimal `main.cyr` smoke test.

## Quick Start

```sh
# Fetch the git-tagged sibling deps (varna, itihas, avatara)
cyrius deps

# Sync the library bundle — regenerate dist/sankhya.cyr from the [lib] module list
cyrius lib sync

# Build + run the CLI smoke test
cyrius build src/main.cyr build/sankhya && ./build/sankhya

# Run the full test suite (32 suites under tests/tcyr/) → "32 passed, 0 failed"
cyrius tests tests/tcyr

# Run the benchmarks (18 benches)
cyrius bench tests/sankhya.bcyr
```

Requires Cyrius 6.4.69 (`cyriusly install 6.4.69`) — pinned in `cyrius.cyml`.

### Use as a dependency

Consumers include the single-file bundle, regenerated by `cyrius distlib`:

```cyrius
include "sankhya/dist/sankhya.cyr"

fn main() {
    alloc_init();

    # Mayan Long Count: 1,872,000 days since creation -> 13.0.0.0.0 (Dec 21, 2012)
    var lc = result_unwrap(long_count_from_days(1872000));
    # lc_baktun(lc) == 13

    # Proleptic Gregorian date -> midnight Julian Day Number (f64)
    var apr1 = gregorian_date_new(2025, GM_APRIL, 1);
    var jdn  = result_unwrap(gregorian_to_jdn(apr1));

    # One JDN, expressed in every calendar sankhya knows
    # (+ itihas historical context & avatara Saptarishi profiles)
    var mcd = result_unwrap(correlate(jdn));

    return 0;
}

var r = main();
syscall(SYS_EXIT, r);
```

Add `sankhya` to your `cyrius.cyml` `[deps]`, and ensure the bundle's folded stdlib deps (`bayan`, `sakshi`, `math`, `ganita`, `net`, `http`) are in your `[deps].stdlib` — the bundle's logging init resolves `SK_INFO` from `sakshi`.

## Integrations (always-on)

| Dependency | Version | Provides |
|-----------|---------|----------|
| `varna` | 2.1.0 | Script rendering: cuneiform, hieroglyphic, Devanagari, Greek alphabetic, CJK rod numerals |
| `itihas` | 2.4.0 | Historical context — eras, civilizations, events on `MultiCalendarDate` |
| `avatara` | 2.9.0 | Saptarishi archetype profiles on `MultiCalendarDate` |
| `bayan` | stdlib | JSON serialize + round-trip parse (replaces serde / serde_json) |
| `sakshi` | stdlib | Structured logging (replaces tracing) |
| `math` + `ganita` | stdlib | f64 constants + extended math (pow / hypot / asin / acos / atan2 / sinh / cosh) for astro |

In the Rust crate `varna`, `itihas`, and `avatara` were optional Cargo features (default off). Cyrius has no feature-flag system yet, so here they are **always-on** — full functional parity, nothing dropped. Re-introducing true optional / feature gating is a backlog item pending Cyrius support.

## Port History

Ported from Rust v2.0.0 (9,857 lines, 17 files) to Cyrius v3.0.0 (10,733 lines across 37 `src/*.cyr` files). The previous Rust source is preserved in `rust-old/` for reference.

- **Modules** — 15 domain modules (`mayan`, `babylonian`, `egyptian`, `vedic`, `chinese`, `greek`, `roman`, `islamic`, `gregorian`, `coptic`, `persian`, `hebrew`, `aztec`, `astro`, `epoch`) over a foundation layer (`error`, `util`, `f64_util`, `logging`), plus a per-module `serial_*.cyr` JSON layer, the `lib.cyr` aggregator, and `main.cyr`.
- **Tests** — 32 `.tcyr` suites under `tests/tcyr/` (plus `tests/foundation.tcyr`), ≈1,346 assertions: per-module 729, serial round-trip 260, integration 198, adversarial / never-panic 159, foundation 22. `cyrius tests tests/tcyr` reports **32 passed, 0 failed**.
- **Benchmarks** — 18 benches in `tests/sankhya.bcyr`: all 16 original Rust criterion benches plus new `coptic` and `aztec` benches.
- **Consumer bundle** — `dist/sankhya.cyr`, regenerated via `cyrius distlib`.
- **Deps** — `bayan` (JSON, replaces serde / serde_json, full round-trip), `sakshi` (logging, replaces tracing), and `math` + `ganita` (f64 / extended math) are folded stdlib; `varna` 2.1.0, `itihas` 2.4.0, and `avatara` 2.9.0 are git-tagged sibling deps, always-on for full parity; `net` / `http` come in transitively to satisfy itihas's bundled hoosh HTTP client (unused by sankhya).
- **Version** — `VERSION` holds `3.0.0`; `cyrius.cyml` derives it via `${file:VERSION}`.

### Cyrius idioms

- No serde derive — each type carries hand-written `<type>_to_json` / `<type>_from_json`.
- `Result` via `Ok` / `sk_fail`, where an error is a `{ code, message }` record.
- `rem_euclid` / `div_euclid` for calendar modulo arithmetic.
- f64 values constructed with `f64_from` / `f64_parse`.
- `#must_use` attributes (bare `#attr`, not Rust's `#[attr]`).
